# Jev 场景训练规则（0.6.0）

规则定义在 server/jev-rules.mjs，版本 scenario-1。它们是应用的教学标准，Jev 判断用户文字是否体现这些标准。不要把概率解释为口才分数或准确率。

## 流程

1. 用户可以手动选汇报、面试、说服、通用表达；自动匹配只看题目，复述模式强制用复述标准。
2. 每个检查点定义“已体现／待补充／需确认”的边界。完整表达没有提到要点属于待补充，不是无法判断。
3. 同一请求批量检查各要点，并分别从原文编号片段中选择相关原话。没有相关句子允许返回 none。
4. 服务端严格校验选项与概率分布；引用只从原文复制。相关句子并不是证明，界面允许回看确认。
5. 汇报优先练具体行动，其他情况按规则顺序选择一个待补充项。任务是应用提供的固定教学提示，不伪装成模型生成文字。
6. 保存记录中修改文字并重新点评，保留上一版文字与结果。只对比同场景、同版本规则；保存文字后再点评也能保留上一版。对比代表文字结果变化，不代表音频表现或掌握程度。

## 本次实测

原样例：项目要延期了。最近事情比较多，人手也不够，所以进度慢了。大家再努力一下，应该就能解决。

最终规则下，Jev 保留“已点明事件”，指出原因不具体、行动、负责人、时间待补充。补全样例五项已体现。补全样例是测试用的虚构情境，不是替用户补写事实。

开发时第一次宽泛“切题”标准误把原样例判为未切题；收窄为只看是否点明题目中的事件后，再对两个样例一起验证。保留最终响应到 tests/fixtures/jev-rules.json。

这只是两条汇报样例的真实验证，不等于其他场景准确率已证实。仍需扩充人工标注样本，包括短表达、错误转写、复述缺原文、模糊时间与角色等。
