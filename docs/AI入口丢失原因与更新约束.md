# AI 点评入口看似丢失：原因与更新检查

## 已确认的原因

0.10.0 及之前的训练与历史界面，将同一个按钮绑定到 `status.ai`：为 true 显示“生成 AI 点评”，为 false 显示“查看基础反馈”。没有单独保留 AI 连接入口，因此状态不可用直接变成功能入口不可见。

初始状态 `ai=false`；`getStatus()` 超过 5 秒或请求失败，也返回 `ai=false, reachable=false`。这些情况下不能据此断言用户未配置模型，但旧界面都走基础反馈分支。后端返回配置未就绪同样触发替换。

此前验证偏重新功能、独立启动及一次模型调用，未设置专门的跨版本升级和状态异常下入口可见性检查。这是回归覆盖缺口。

## 尚不能断言的部分

用户上次反馈时，实际服务返回 `ai=false`，而随后检查发现保存的地址、模型和加密密钥存在且可读取；启动新版后又恢复正常。缺少当时运行环境的完整诊断证据，不能断言更新删除了密钥，也不能把状态异常确定归因于网络或 Windows 加密。

现有代码固定使用 `%APPDATA%/KaikouPractice`，不是按版本新建配置目录；升级不应更改此位置。界面入口丢失原因已确定，运行状态为什么当时变为 false 仍需区分，不混为一个结论。

## 已落实的防回归措施

- 0.10.1 已保留 AI 入口和应用内配置、重新检查入口，基础反馈独立展示。
- 明确请求 AI 时，配置失效返回错误，不静默降级成基础反馈。
- 新增状态异常测试，覆盖新练习、历史记录的断网、503 配置读取失败和超过 5 秒的启动响应。
- 新增 `desktop/upgrade-test.mjs`：旧版写入虚构密钥和练习，退出后用新版启动同一隔离数据目录，检查密文未被覆盖、配置可读、练习保留、两处 AI 入口可见；不发送模型请求。
- 根目录 `AGENTS.md` 已写入以后每次应用更新必须保留入口并执行这些测试的要求。

执行跨版本检查：`npm run test:upgrade -- <旧版exe绝对路径> <新版exe绝对路径>`。测试使用独立端口及隐藏窗口，不读取或覆盖真实配置。
